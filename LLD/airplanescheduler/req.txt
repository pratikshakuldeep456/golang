The Airport Scheduler (single runway) problem is basically an LLD/concurrency problem 
where you need to schedule flights that all want to use one shared runway. 


We have a single runway,
and multiple flights can request landing or takeoff.
The scheduler should assign the runway without overlapping schedules

Flight has LANDING or TAKEOFF.
Each operation takes some duration.
Flights can have a requested/preferred time.
Only one flight can occupy the runway at a time.
Need to handle cancellations/rescheduling.
Assume emergency flights can have higher priority if required.
Initially assume in-memory system; persistence/concurrency can be discussed separately.

Main responsibility
The important separation is:

    → coordinates everything

    → decides WHICH flight gets priority

    → represents WHEN the runway is reserved

in distributed system may have multiple scheduler instances,

Both see:

10:00–10:10 → occupied
10:10–10:20 → available

Both try to reserve:

A → 10:10–10:20
B → 10:10–10:20

❌ That's the distributed race condition.

The database becomes the source of truth for runway reservations.

You can use a transaction:

BEGIN;

-- Lock the relevant schedule/resource
SELECT *
FROM runway_slots
WHERE runway_id = 'R1'
ORDER BY start_time
FOR UPDATE;

-- Check whether 10:10–10:20 is free

-- If free:
INSERT INTO runway_slots
    (runway_id, start_time, end_time, flight_id)
VALUES
    ('R1', '10:10', '10:20', 'F2');

COMMIT;
