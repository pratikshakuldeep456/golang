Data structures

Each floor holds a list of its spots.
For every spot type, a min-heap of free spots, ordered by floor then number, with a mutex on it.
Entry pops the nearest free spot. Exit pushes it back.
Tickets are kept in a map by ticket ID, so lookup at exit is O(1).
Payments are kept in a map by idempotency key, so a retry never charges twice.

Design patterns

A PaymentStrategy interface, with UPIPayment and CardPayment implementing it, picked by a factory.
A PricingStrategy for vehicle type, festive and peak-hour rules.
A new payment method or pricing rule is a new class, so existing code doesn’t change (Open/Closed Principle).

A user pays at the exit, but the app crashes or the network drops, and the user taps pay again. How do you make sure they’re not charged twice, and what state is the spot in?
he user is charged only once, because every payment attempt carries an idempotency key. When the user taps pay, the client sends the key with the request, and the payment service first checks the key. If the key is new, it creates a Payment record as Pending, charges through the payment strategy, and saves the result under that key. If the user taps again after a crash or a network drop, the key is found, and the service returns the stored result and never calls the gateway a second time. If the first attempt is still in progress, the second request waits or gets ‘in progress’ and doesn’t start a new charge.
The spot stays Occupied the whole time. It’s released only after the payment succeeds, so a failed or interrupted payment never frees a spot early. If payment fails, the ticket stays Active, and the user can retry, with the same key for the same attempt or a new one after a failure. Releasing the spot is idempotent too: it’s done only when the ticket moves from Active to Closed, so a retry can’t release it twice.”

The key is generated per payment attempt, often on the client, and the server stores it with the payment in a map with a unique constraint.
A conditional update (Pending → Success) makes the status change safe against a duplicate gateway callback.
Keep keys for a limited time (say 24 hours) and then clear them.
