You only ever call .Execute() on the first box. You never manually call box 2 or box 3 yourself. The magic is that box 1's Execute calls
 box 2's Execute, which calls box 3's Execute
  — like dominoes falling.
  Because without the wrapper, you'd have to write this manually every time:
  With ChainStep, you build the order once, then just call one line, forever:

ProcessingStep = the interface / rulebook ("must have Execute")
ValidationStep, TransformationStep, PersistenceStep = the actual workers who follow that rulebook
ChainStep = a box/node that holds one worker + a pointer to the next box, and its own Execute is really just "run my worker, 
then forward the request to the next box"
